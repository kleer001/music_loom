## What this rung is for

Turning an inspiration into something buildable, and then — once it plays —
turning the running instrument back on the spec to see what it actually became.

Read this twice: once while shaping the idea, once when the slice plays. The
second read is the useful one. The first is guesses; the second has an
instrument to argue with.

## The five questions

Grade the idea against these before building. Answers must name mechanisms, not
feelings.

1. **What does a listener hear in the first four bars?** If the answer needs a
   paragraph of context, the instrument does not have a sound yet — it has a
   concept.
2. **Which single gesture carries it?** Every instrument worth building has one:
   the feedback throw, the breath, the filter opening, the note that bends. Name
   it. If you cannot, you are building a genre, not an instrument.
3. **What varies, and what stays still?** Something has to hold while something
   else moves. An instrument where everything modulates is noise; one where
   nothing does is a loop.
4. **What is it made of that you cannot synthesise?** Every sample is a rights
   question (`RIGHTS.md`) and a distribution weight. Being honest here early is
   cheaper than being honest at the release gate.
5. **How would you know it failed?** Name the measurement. "It would sound
   wrong" is not one.

## Reading the spec against the running instrument

Once it plays, the useful questions change:

- What did you build that the spec did not ask for? Keep it or cut it, but
  notice it.
- What did the spec ask for that you skipped? Usually because it turned out not
  to matter — which is worth knowing.
- Which numbers in the code came from the digest, and which drifted while you
  were tuning by ear? Drifted ones need either a comment saying they were tuned,
  or a return to the digest value.
