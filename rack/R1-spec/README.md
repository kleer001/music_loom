## What this rung is for

Turning an inspiration into something buildable, and then — once it plays — turning the running instrument back on the spec to see what it actually became.

This page reads differently the two times it gets read. Before building, the answers are guesses. Once the slice plays, there is an instrument to argue with, and that read is the one that changes things.

## The five questions

Answers that name mechanisms go further here than answers that name feelings.

1. **What does a listener hear in the first four bars?** An answer that needs a paragraph of context is describing a concept; the sound comes later.
2. **Which single gesture carries it?** The feedback throw, the breath, the filter opening, the note that bends. An idea with no nameable gesture is usually still a genre rather than an instrument.
3. **What varies, and what stays still?** Something holding while something else moves is what reads as motion. Everything modulating reads as noise; nothing modulating reads as a loop.
4. **What is it made of that you cannot synthesise?** Every sample is a rights question (`RIGHTS.md`) and a distribution weight. Both are cheaper to answer now than at the release gate.
5. **How would you know it failed?** The measurement, named. "It would sound wrong" is not one that a harness can read.

## Reading the spec against the running instrument

Once it plays, the useful questions change:

- What did you build that the spec did not ask for? Keeping it and cutting it are both fine; not noticing it is how a spec goes stale.
- What did the spec ask for that you skipped? Usually because it turned out not to matter — which is worth knowing.
- Which numbers in the code came from the digest, and which drifted while you were tuning by ear? A drifted number reads as a sourced one unless a comment says otherwise.
